## Tests

Both packages use [Vitest](https://vitest.dev/); the app adds [Testing Library](https://testing-library.com/docs/react-testing-library/intro/) and runs in jsdom. Tests sit beside the code they cover as `*.test.ts` or `*.test.tsx`.

```bash
npm run test          # watch mode, both packages
npm run test:run      # run once
npm run test:coverage
npm run test --workspace=@dna/app   # one package
```

### Rendering components

Most components need the app's providers (React Query, theme, auth, events, feature flags, terminology). Use the helper in `src/test/render.tsx` instead of Testing Library's `render`; it wraps the component in all of them, with a React Query client that doesn't retry:

```tsx
import { render, screen } from '../test/render';

it('shows the version name', () => {
  render(<VersionCard version={version} />);
  expect(screen.getByText('TST_010_0020_anim_v060')).toBeInTheDocument();
});
```

Tests run with `VITE_NOMENCLATURE` cleared, so they always see DNA's default terms.

## Formatting and type checks

```bash
npm run format        # format with Prettier
npm run format:check  # check only
npm run typecheck     # tsc across both packages
```

## In CI

Pushes and pull requests that change frontend source files (`.ts`, `.tsx`, `.json`, `.css`, `.md` under `frontend/`) run the **Frontend Code Formatting and Type Checking** workflow: `npm ci`, then `npm run format:check` and `npm run typecheck`. Run both locally before pushing.
