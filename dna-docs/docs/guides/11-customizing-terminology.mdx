## Why customize terminology

Every studio has its own words for the same things. One studio reviews **versions** in a **playlist**, another reviews **takes** in a **review session**, and a third tracks everything in **ShotGrid** instead of a generic "production tracking" system. DNA lets you rename the text shown in the frontend to match your studio, without forking the code.

Only text displayed to the user changes: labels, placeholders, tooltips, dialog titles, toast messages, hotkey names in Settings, and the PDF export summary. Component names, API paths, and stored data are not affected.

## What you can rename

Each term is set with a short JSON object. Anything you leave out keeps the DNA default.

| Term key | Default | Fields |
| --- | --- | --- |
| `version` | Version / Versions | `singular`, `plural` |
| `playlist` | Playlist / Playlists | `singular`, `plural` |
| `project` | Project / Projects | `singular`, `plural` |
| `shot` | Shot / Shots | `singular`, `plural` |
| `asset` | Asset / Assets | `singular`, `plural` |
| `task` | Task / Tasks | `singular`, `plural` |
| `note` | Note / Notes | `singular`, `plural` |
| `status` | Status / Statuses | `singular`, `plural` |
| `productionTracking` | Production tracking | `singular`, `plural`, `short` (default `PT`) |
| `publish` | Publish / Published / Publishing | `verb`, `past`, `progressive` |

Write each value the way it should appear at the start of a sentence or in a title, for example `"Review Session"`. DNA builds the lowercase form it needs mid-sentence on its own.

## Setting it up

Terminology is set with the `VITE_NOMENCLATURE` environment variable. It holds a single line of JSON.

### Local development

Add the variable to `frontend/packages/app/.env`:

```bash
VITE_NOMENCLATURE={"version":{"singular":"Take","plural":"Takes"},"playlist":{"singular":"Review Session"},"productionTracking":{"singular":"ShotGrid","short":"SG"}}
```

Restart the dev server after changing it.

### Docker image

Pass the JSON as a build argument when you build the frontend image:

```bash
docker build \
  --build-arg VITE_NOMENCLATURE='{"version":{"singular":"Take","plural":"Takes"}}' \
  -t dna-frontend frontend/
```

:::note
`VITE_NOMENCLATURE` is baked into the frontend at build time, like the other `VITE_` settings. Changing it requires a rebuild.
:::

If the variable is unset, DNA uses its default wording.

## Worked example

A studio that says **Take**, **Review Session**, and **ShotGrid** sets:

```json
{
  "version": { "singular": "Take", "plural": "Takes" },
  "playlist": { "singular": "Review Session", "plural": "Review Sessions" },
  "productionTracking": { "singular": "ShotGrid", "short": "SG" }
}
```

The frontend then changes like this:

| Where | Default | With the example |
| --- | --- | --- |
| Sidebar empty state | Select a playlist to view versions | Select a review session to view takes |
| Header buttons | Previous Version / Next Version | Previous Take / Next Take |
| Header metadata | Version Status: | Take Status: |
| Header link | PT tab | SG tab |
| Settings, keybindings | Next Version | Next Take |
| Publish dialog description | Review and publish notes and transcripts to production tracking. | Review and publish notes and transcripts to ShotGrid. |

## How values are resolved

- **Partial overrides merge.** You only need to list the terms and fields you want to change.
- **Plurals are derived when omitted.** If you set `singular` and leave out `plural`, DNA adds `s`, `es`, or `ies` as appropriate (`Review Session` becomes `Review Sessions`). Set `plural` yourself when that is wrong for your word.
- **Publish forms are derived from the verb.** If you set only `verb` (for example `Release`), DNA derives `past` (`Released`) and `progressive` (`Releasing`). Set them explicitly for irregular verbs.
- **Lowercase forms keep brand names.** Terms are lowercased when used mid-sentence (`Review Session` becomes `review session`). A word with a capital letter after its first letter, such as `ShotGrid` or `PT`, is left as written.
- **Bad input is ignored.** Invalid JSON, unknown terms, unknown fields, and blank or non-text values are skipped, and a warning is written to the browser console. The rest of the configuration still applies.

## What is not renamed

- "In Review", "Transcript" and "Transcription", and "Scratch Pad". See [In Review](/docs/4-in-reivew) and [Transcription](/docs/5-transcription).
- The product name, "Dailies Notes Assistant".
- CSV export column headers. They follow the ShotGrid note import layout and are configured separately with `VITE_REVIEW_CSV_COLUMNS`.
- API paths, stored data, and file names such as exported review files.
